# Determine Matrix message send and download times using origin_server_ts and unsigned age fields

## Summary

Every Matrix message event carries an `origin_server_ts` field, generated by the Matrix homeserver itself rather than by the sending client, recording when the server received the message; a separate `age` field inside the event's `unsigned` object is updated by the server at the moment a specific client downloads the event, so subtracting is not needed — adding the two values together yields the download timestamp for that client's copy of the event.

## Details

Because `origin_server_ts` is generated server-side and is not part of the client-editable message content, an investigator can trust it as the message's true send time to the server even if the sending client's local clock was incorrect, provided the server's own clock was correct at the time — which can itself be checked by an investigator sending a controlled test message and comparing the noted send time against the returned `origin_server_ts`. The `age` value, by contrast, sits inside the `unsigned` object, which by protocol design is excluded from the cryptographic signing process applied to the rest of the event and is refreshed by the server each time the event is (re-)downloaded by a client; experiments confirmed `age` is unaffected by an incorrect local client clock, and that combining `origin_server_ts` and `age` for a given exported event recovers the moment that specific client downloaded it, which can differ across clients and across repeated downloads by the same client. A related `unsigned` field, `transaction_id`, is generated by the sending client itself (and inherits the client's local-clock error, if any) and is visible only in the sender's own copy of the event, so its presence can help identify which client actually sent a given message.

## Examples

- Sending a text message from a controlled account with the local system clock set four days in the past confirmed `origin_server_ts` still reflected the real (server) send time rather than the client's incorrect local clock, validating it as a reliable server-side timestamp.
- Adding the `origin_server_ts` and `age` values recorded for six messages exported from a receiving client's copy of a room consistently reproduced the real-world time each message was downloaded by that client, even when the client computer's own clock had been deliberately set incorrectly.
