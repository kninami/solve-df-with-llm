# Detect and transcribe speech in forensic audio and video evidence using voice activity detection and open-source ASR

## Summary

Digital forensic laboratories are often time-, resource-, and budget-constrained, and manually listening to every audio/video file in a case to judge investigative relevance is slow; automated speech-to-text addresses this, but many available automatic speech recognition (ASR) systems either require cloud connectivity (undesirable or prohibited for case evidence in many jurisdictions) or are closed-source. Combining an open-source voice activity detection (VAD) library with an open-source, locally-executable ASR engine (Mozilla's DeepSpeech) lets an investigator automatically flag which files in a case contain speech above a configurable duration/percentage threshold, then transcribe only those files entirely on local infrastructure.

## Details

The pipeline runs as two integrated modules built for the Autopsy digital forensics platform. First, VAD is performed per audio file by a CNN-based segmenter (inaSpeechSegmenter) that classifies each segment of the file as speech, music, noise, or no-energy and additionally estimates speaker gender for speech segments; files are tagged as containing speech only if both the total speech duration and the percentage of speech-bearing content exceed investigator-configurable thresholds, avoiding wasted transcription effort on files that are mostly silence, music, or noise. Speech-tagged files are then transcribed by a DeepSpeech-based transcription module (deepspeech_csv), which converts each qualifying audio file to a standard 16kHz mono 16-bit PCM WAV format (via ffmpeg) before transcription, and imports the resulting transcript into the Autopsy case as a searchable extracted-text artifact, making the spoken content available to Autopsy's existing keyword-search functionality. A companion report module can generate an HTML or CSV transcript report for files the investigator has manually tagged for transcription, and a standalone command-line script variant allows the same detection-and-transcription pipeline to run independently of Autopsy. Because both the VAD and ASR components run entirely locally (with optional GPU acceleration), no case audio data needs to be transmitted to a third-party cloud service, addressing a common evidentiary-handling and privacy constraint that rules out many commercial cloud-based ASR options for forensic use.

## Examples

- Tested against the LibriSpeech test-clean corpus (2,619 clean, native-English-speaker recordings), the pipeline achieved a 7.80% Word Error Rate (WER), comparable to but somewhat higher than figures separately reported for the same underlying ASR engine and dataset by its own developers (5.3%-7.06%), and processed the full corpus with a real-time factor of 0.16 using GPU acceleration (0.42 using CPU only).
- In a simulated real-world scenario, voice messages generated by 14 popular Android messaging, note-taking, and videoconferencing applications (WhatsApp, Telegram, Viber, WeChat, Facebook Messenger, Zoom, Microsoft Teams, and others) were installed on a rooted test smartphone; the pipeline automatically detected and transcribed voice recordings from 10 of the 14 applications without any manual intervention, correctly identifying every voice recording that fulfilled the configured speech-duration and speech-percentage thresholds as containing speech.
- Transcribing 20 recovered voice messages sent between non-native English speakers through the tested applications, the pipeline's WER ranged from 17.0% to 35.0% (average 26.4%) -- substantially higher than the clean-speech benchmark result -- while still producing transcripts the authors judged adequate for quickly locating relevant information during triage, even though the WER precluded direct use of the raw automated transcript in a formal forensic report without manual review.
