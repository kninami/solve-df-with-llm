# Apply the five-questions tool-fitness framework before deploying an unfamiliar forensic tool

## Summary

Before relying on a forensic tool's output, explicitly answer and document five questions about it: what it does, how it is used, how it produces its results, whether it does so correctly, and whether its use is authorized — surfacing documentation gaps, testing gaps, and authorization gaps before they affect casework rather than after.

## Addresses

- [[weaknesses/Tool documentation gaps and insufficient testing lead practitioners to misunderstand or misapply a forensic tool's capability]]

## How To Apply

For any tool not already well-understood by the practitioner, work through the five questions in order, actively seeking out (rather than assuming) the answers: consult vendor documentation and, where it is vague or silent, unpack complex functionality claims into their component parts; confirm the configuration and operating conditions the vendor requires; seek evidence of independent or in-house testing demonstrating the tool performs as claimed under conditions similar to the current case; and check organizational, legal, and accreditation requirements for authorization to use the tool for this task. Record the answers as part of the case's contemporaneous notes so the decision to use the tool is evidenced and can be reviewed later.
